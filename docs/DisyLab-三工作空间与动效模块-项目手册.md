# DisyLab 三工作空间与动效模块项目手册

> 文档版本：v1.1  
> 编制日期：2026-08-21  
> 计划启动：2026-08-24  
> 项目代号：Disy Motion  
> 状态：开发基线

## 1. 项目结论

DisyLab 将从单一无限画布升级为一个统一项目容器下的三类工作空间：

1. **设计**：AI 图像/视频生成、素材组织、提示词、参考关系与视觉方案生产。
2. **动效**：以 Jitter 类完整动效工作流为产品对标，实现设计编辑、时间轴、动画预设、模板库、实时预览、多格式导出、批量生产与 AI 辅助动效。
3. **白板**：用于头脑风暴、流程图、设计规划、信息架构、便签和团队讨论。

三类工作空间共享项目、资产库、历史、Agent、导入导出和品牌视觉系统，但拥有独立的数据模型、编辑器状态和工具栏。当前产品线优先完整建设“动效”；设计保持兼容，白板保留产品入口与数据扩展位。动效不以轻量 MVP 为终点，MVP 只是可持续迭代的第一个交付门槛，正式目标是覆盖 Jitter 类工具从设计、动画、模板到导出的主工作流。

## 2. 产品目标

### 2.1 核心目标

- 用户可从工作空间入口创建“设计 / 动效 / 白板”三种画布。
- 设计空间中的图片、SVG、文字、视频可发送到动效空间继续制作。
- 动效空间可完成 5–30 秒的品牌动画、社媒动图、Logo 动效、文字动效和产品展示短片。
- 动效操作对非专业动画用户友好：优先使用“动作 + 预设”，同时允许关键帧精调。
- 项目数据本地优先，旧 `.disy` 项目可直接打开。
- MVP 支持稳定预览、撤销重做、保存恢复和至少一种可靠成品导出。
- 正式版具备模板库、完整时间轴、多场景、文字动画、组件、音视频、多格式与批量导出。
- 用户可使用官方模板、项目模板和个人模板，并替换文字/图片快速生成变体。

### 2.2 非目标

下列能力不属于近期 Jitter 功能对标范围：

- 多人实时协作、云端账号与权限系统。
- 复杂 3D、粒子系统、骨骼动画和专业调色。
- 完整白板编辑器。
- 依赖 Jitter 私有 API、自动化网页或 iframe 嵌入。

ProRes、4K/120fps、透明视频和服务端渲染属于长期导出能力，不在 MVP 承诺中，但数据模型和导出接口必须为其预留。

## 3. 用户与场景

### 3.1 目标用户

- 需要快速制作社媒动效的平面设计师。
- 使用 AI 生成视觉素材的内容创作者。
- 需要 Logo、标题、卡片和产品展示动画的独立开发者。
- 需要从创意规划一路走到视觉与动效交付的小团队。

### 3.2 首期重点场景

1. 设计空间生成海报，发送到动效空间，添加标题入场与背景缩放，导出 MP4/GIF。
2. 导入 SVG Logo，选择描边/显现/弹性缩放预设，导出 Lottie 或透明 WebM（后续里程碑）。
3. 将多张产品图放入场景，通过错峰动画生成 10 秒产品轮播。
4. 通过自然语言提出“让标题更有冲击力”，Agent 返回可编辑的动画参数，而不是不可修改的视频结果。

## 4. 三工作空间信息架构

| 维度 | 设计 | 动效 | 白板 |
|---|---|---|---|
| 核心对象 | 生成/上传节点与关系 | 场景、图层、动画轨道 | 便签、形状、连线、分区 |
| 时间概念 | 无强制时间轴 | 帧、秒、播放头、场景时长 | 无强制时间轴 |
| 主要输出 | 图片、视频素材、方案 | MP4/WebM/GIF/Lottie | PNG/PDF/结构数据 |
| 主交互 | 无限画布、节点连接 | 舞台 + 图层 + 时间轴 | 无限画布、自由连接 |
| AI 角色 | 生成与方案 Agent | 动效编排与参数 Agent | 总结、发散、结构化 Agent |

### 4.1 共享层

- 项目与画布管理。
- 资产库、生成历史、输出历史。
- API 连接和模型配置。
- Agent 会话与上下文引用。
- `.disy` 项目包与媒体去重。
- 主题、快捷键、通知、错误处理。

### 4.2 隔离层

- 每种工作空间拥有自己的 schema 版本。
- 不允许动效时间轴状态污染设计节点数据。
- 工作空间切换时销毁专属快捷键、播放循环和临时 URL。
- 跨空间使用显式“发送到…”命令并生成资产引用，不直接共享可变对象。

## 5. 动效模块产品范围

### 5.1 P0：必须交付

- 动效工作空间创建、打开、重命名、复制、删除。
- 舞台尺寸、背景色、时长、帧率设置。
- 图层：文字、图片、SVG、基础形状、视频。
- 图层排序、显隐、锁定、重命名、编组基础能力。
- 变换属性：位置、缩放、旋转、透明度。
- 时间轴：播放头、缩放、拖拽、关键帧创建/移动/删除。
- 缓动：Linear、Ease In/Out/In-Out、Back、Elastic、Bounce。
- 入场/强调/退场预设，支持覆盖或追加。
- 实时预览、循环播放、暂停、跳转首尾。
- 撤销/重做、自动保存、刷新恢复、旧项目兼容。
- MP4 或 WebM 至少一种稳定导出；GIF 为目标项。

### 5.2 P1：首个稳定版

- 文字按行/词/字拆分与错峰。
- 遮罩、模糊、圆角、渐变和混合模式。
- 自定义 cubic-bezier 缓动。
- 路径运动与基础 SVG Morph。
- 动画复制粘贴、保存为个人预设。
- 多场景与场景排序。
- Lottie 导入/导出兼容子集。
- 跨比例复制与基础自适应。

### 5.3 P2：增强能力

- 音频轨、波形、音量和淡入淡出。
- AI 动效指令转结构化动画。
- 批量文案/素材替换和批量导出。
- 透明 WebM、帧序列、高级导出队列。
- 动效组件和跨项目模板。

### 5.4 正式版功能域

正式版必须形成以下完整产品域，详细状态见《Jitter 类功能对标清单》：

- **设计编辑**：无限场景画布、图层、形状、钢笔、文字、图片、SVG、视频、音频、对齐、吸附、编组、遮罩、渐变、模糊和混合模式。
- **动画编辑**：完整时间轴、关键帧、动作片段、入场/强调/退场、缓动、错峰、路径运动、Morph、循环和动画复制复用。
- **文字动画**：按行、词、字符拆分，打字、滚动、遮罩揭示、字距和路径类效果。
- **模板库**：官方模板、分类、搜索、预览、收藏、最近使用、个人模板、团队模板扩展位和一键套用。
- **组件系统**：可复用动效组件、实例覆盖、源组件更新和跨项目复用。
- **多场景生产**：场景复制、排序、比例适配、批量替换文字与素材、批量生成变体。
- **导出中心**：MP4、WebM、GIF、Lottie、透明视频、静态帧、帧序列、分辨率/FPS/质量/循环参数和批量队列。
- **AI 动效**：自然语言生成可编辑动画、效果变体、自动适配比例与语言、模板内容批量替换。

## 6. 核心体验原则

1. **先预设，后精调**：首次操作不要求理解关键帧。
2. **所见即所得**：舞台预览与导出使用同一动画解释规则。
3. **动作可组合**：入场、强调、退场可以叠加，冲突必须可解释。
4. **参数可回退**：应用预设前记录变更，支持单步撤销。
5. **时间始终明确**：所有动画显示开始时间、持续时间和结束时间。
6. **性能降级可见**：素材过大或图层过多时提示代理预览，不静默卡顿。
7. **数据不丢失**：编辑状态与导出任务解耦，导出失败不影响项目。

## 7. MVP 交互布局

```text
┌ 顶栏：返回 / 文件名 / 尺寸 / 预览 / 导出 ───────────────┐
│ 左：素材/文字/形状/预设 │ 中：舞台 │ 右：属性/动画      │
│                         │          │                    │
├─────────────────────────┴──────────┴────────────────────┤
│ 图层列表 │ 时间刻度、播放头、关键帧与动画片段            │
└─────────────────────────────────────────────────────────┘
```

小屏不承诺完整编辑体验；首期桌面端最低建议宽度 1280px。

## 8. 成功指标

### 8.1 产品指标

- 新用户在 5 分钟内完成一次“导入素材 → 应用预设 → 导出”。
- P0 模板在主流桌面 Chrome/Edge 中预览与导出无明显差异。
- 10 秒、20 图层、每层 4 个属性轨道的工程保持可编辑。
- 自动保存后刷新页面，画面、时间轴、当前场景完整恢复。

### 8.2 工程质量门槛

- `npm run typecheck` 通过。
- 动画时间计算、迁移、序列化具备单元测试。
- 关键用户路径具备手工验收清单；核心路径增加浏览器自动化测试后再进入稳定版。
- 导出失败必须返回可理解原因并允许重试。
- 不把业务逻辑继续集中进 `src/App.tsx`。

## 9. 关键决策

| 编号 | 决策 | 原因 |
|---|---|---|
| ADR-001 | 自研动效数据模型，不依赖 Jitter 内部格式 | 可控、可维护、无第三方接口风险 |
| ADR-002 | 预览内核与导出解释器共享时间计算 | 避免预览与成品不一致 |
| ADR-003 | 工作空间使用带版本的 discriminated union | 保证三类数据隔离和迁移能力 |
| ADR-004 | MVP 采用单场景，模型预留多场景 | 控制首期范围，避免后期重写 |
| ADR-005 | 动画属性使用标准化轨道，预设只是轨道生成器 | 预设可编辑、可组合、可持久化 |
| ADR-006 | 首期面向桌面 Chromium | 时间轴与浏览器导出对性能和 API 要求较高 |

## 10. 风险登记

| 风险 | 等级 | 应对 |
|---|---:|---|
| `App.tsx` 继续膨胀导致高耦合 | 高 | 第 0 周先拆 workspace router 与 motion 模块 |
| 浏览器视频编码兼容性差异 | 高 | 第 1 周做导出技术尖峰，确定 WebCodecs/ffmpeg 方案 |
| Lottie 无法表达全部 CSS/文本动画 | 高 | 明确兼容子集，导出前做能力检查 |
| 大视频/大图导致内存峰值 | 高 | 代理预览、尺寸限制、分阶段释放 Blob URL |
| 动画轨道冲突和组合规则不清 | 中 | 属性单写者原则 + 显式覆盖提示 |
| 旧项目迁移失败 | 高 | schema version、纯函数迁移、夹具测试、导入备份 |
| 排期被白板需求分散 | 中 | 白板仅建立类型与入口，完整开发另立项目 |

## 11. Definition of Done

一个功能只有同时满足以下条件才算完成：

- 交互、空状态、错误状态和快捷键已实现。
- 数据可保存、恢复、导入和导出。
- 撤销/重做行为明确。
- 有与风险相称的自动测试或可重复验收步骤。
- 类型检查和生产构建通过。
- 文档和变更记录已更新。
- 不引入未说明的旧项目破坏性变更。

## 12. 项目治理

- 产品范围以本手册 P0/P1/P2 为准。
- 技术边界和目录结构以《技术实施方案》为准。
- 日期、责任和验收以《开发排期》为准。
- 每周一冻结本周目标；周三做风险检查；周五演示并决定是否进入下一门槛。
- 所有新增需求先标注 P0/P1/P2，不允许口头插入当前 Sprint。
