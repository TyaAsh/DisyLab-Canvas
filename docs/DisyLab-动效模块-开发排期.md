## 2. 周排期

### 第 0 周：08-24 ～ 08-28｜架构与风险尖峰

目标：在大规模编码前消除存储迁移、播放内核和视频导出三项最大风险。

- 建立 `WorkspaceKind` 与三工作空间创建入口原型。
- 旧画布默认迁移为 `design`，增加 schema/迁移测试。
- 建立 motion 目录、类型、默认文档和独立 store 骨架。
- 完成 easing、插值和 `sampleLayerAt(timeMs)` 原型。
- 制作 3 图层、10 秒、30fps 导出原型，对比 WebCodecs、MediaRecorder、ffmpeg.wasm。
- 输出 ADR：P0 导出格式与技术路线。
- 明确 `App.tsx` 适配边界，不在主文件继续增加时间轴业务。

周五演示：创建三类工作空间；打开动效空白舞台；播放三个程序化图层；下载一份原型视频。

### 第 1 周：08-31 ～ 09-04｜动效舞台与图层

- 完成 MotionWorkspace 主布局。
- 舞台尺寸、背景、缩放与适配窗口。
- 文字、图片、SVG、基础形状图层。
- 图层创建、选中、移动、缩放、旋转、排序、显隐、锁定和删除。
- 项目资产选择器和设计 → 动效素材快照。
- 自动保存、刷新恢复、基础错误边界。

验收：用设计空间的一张图片创建动效项目，添加文字与 SVG，刷新后布局一致。

### 第 2 周：09-07 ～ 09-11｜属性面板与历史

- 统一变换属性模型。
- 右侧属性面板与数值输入。
- 对齐、吸附和基础多选。
- command 系统、撤销/重做、拖拽历史合并。
- 素材替换与来源更新。
- 增加 P0 单元测试基线。

验收：连续完成 20 次编辑，可逐步撤销/重做；关闭重开无数据漂移。

### 第 3 周：09-14 ～ 09-18｜时间轴基础

- 时间标尺、播放头、播放/暂停、循环。
- 图层 in/out 区间。
- 时间轴缩放、滚动、按帧吸附。
- 属性轨道展开收起。
- 关键帧创建、选择、移动和删除。
- Space、Delete、Home、End 快捷键。

验收：位置、缩放、旋转、透明度可各自创建关键帧并稳定播放。

### 第 4 周：09-21 ～ 09-25｜缓动与预设

- Linear、Ease、Back、Elastic、Bounce。
- 预设注册表、预览卡和参数表单。
- 首批 12–18 个入场/强调/退场预设。
- 预设覆盖冲突提示。
- 动画复制/粘贴。
- 播放性能优化，避免 React 每帧整树刷新。

验收：从空项目到完成三图层错峰动画不超过 3 分钟；预设应用后关键帧可继续编辑。

### 第 5 周：09-28 ～ 10-02｜导出与 MVP 收口

- 固定时间步离线采样。
- P0 视频格式导出、进度、取消、失败重试。
- 字体、图片、SVG 和视频素材预检。
- 输出历史和资产库回写。
- 全量类型检查、构建、核心回归和内存检查。
- 完成使用说明、已知限制和 MVP 发布说明。

MVP 验收：完成“设计素材 → 动效预设 → 时间轴调整 → 导出 → 回到资产库”的闭环。

### 第 6 周：10-05 ～ 10-09｜真实案例与稳定性

- 制作 5 个黄金案例：Logo、标题、海报、产品卡片、短视频混排。

- 代理预览、资源释放和错误文案。
- 修复用户测试中的 P0/P1 缺陷。

## 6. 缺陷门槛

- **Blocker**：数据丢失、无法打开项目、导出文件损坏。发现即停止新功能。
- **P0**：主路径不可完成、严重预览/导出不一致。里程碑前必须清零。
- **P1**：有替代路径但明显影响使用。Beta 前清零或书面接受。
- **P2**：视觉和易用性优化，可进入后续迭代。

## 7. 工期调整规则

如果只有兼职投入，保持阶段顺序不变，优先延期 P1/Beta，不压缩 M0 技术尖峰和 MVP 测试。若 P0 导出尖峰在 08-28 前未通过，MVP 日期顺延一周，同时将首版格式收敛为 WebM；不得用不稳定实时录屏冒充稳定导出。

若增加第二名开发者，可并行拆分：主开发负责模型、播放、时间轴；第二开发负责舞台 UI、素材接入、导出体验和测试。两人仍通过同一 MotionDocument schema 集成。
